## What changed

The shared client already deliberately emits `ApiError` with `message`, `status`, `code` and `detail`, and deliberately does **not** expose `.response`. The existing tests pin that contract and the 500 payload leak barrier. This change retains both. `utils/errorHandler.ts` now provides one message parser (`getErrorMessage`, with `apiDetailMessage` retained as an alias), plus status/detail readers. They understand canonical errors and raw axios adapters. Validation arrays remain plain text and retain the field name; structured business rejections use their message. Safe-stop/network guidance from the client survives.

The obsolete text extraction was much wider than the prompt's approximate 18 screens. The migrated files change error presentation only: helper imports and rejected-request message/status extraction. Request payloads, success paths and business rules are unchanged. Existing per-screen parsers now delegate to the same helper. The four Shopify sync-screen substitutions are intentionally small to compose with Prompts A-C. Catalogue overlap is limited to `CatalogProductDrawer.tsx` and `CataloguingScorecardPage.tsx`; Prompt D's SettingsStore, quick-add, category labels and variant table are untouched.

The two backend changes are test-harness/fixture fixes only:

* `test_catalog_guard` was leaking created products into the next test when Mongo was absent. HTTP dependencies use `get_seeded_db()`, but the session isolation fixture reset only `get_db()` (the disconnected real connection). The second and third valid creates received `409 DUPLICATE_PRODUCT`, not a GST calculation failure. Resetting the effective connection isolates the local seeded database exactly as CI's real Mongo database is isolated. No assertions or duplicate guards were removed.
* The stale release fixture stamped `datetime.now()` without a timezone. Production correctly reads legacy naive timestamps as UTC. On an IST workstation, a purported six-minute-old claim therefore looked five hours and 24 minutes in the future. The fixture now writes an aware UTC instant. The release/claim implementation and the stock-count expectation are unchanged.
