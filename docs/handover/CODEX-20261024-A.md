First publication now leaves siblings missing required colour/size options off
the Shopify payload. Complete siblings retain their own SKU, barcode, price,
stock and photographs. Live retry does not duplicate or replace the previously
created variant IDs.

Review fixes (Claude, review of #1276): the lead is NOT re-queued for an omitted
sibling. Filling in the sibling's colour/size goes through the product edit door,
which queues the model's listing (`product_master.queue_model_listing_of`), so the
corrected sibling joins the same page on the next run; re-queueing on every run
only re-sent the same page (and also caught the seeding step's own data hold).
"Left off for a missing option" is now one marker on the hold
(`missing_option`), read through one helper (`shopify_push.missing_option_holds`
/ `only_missing_options`) by the scheduled run and the bulk press, never by the
reason text.

The run ledger and existing sync page name each omitted SKU in an amber warning.
The manual bulk-push summary counts omitted options separately from stock
warnings; a successful partial family publish no longer invents a stock failure.
Other price, stock, identity and seed failures remain visible. A lead lacking a
required option still refuses publication: no substitute lead or identity change.
First-publication OPTION_CLASH remains a whole-family refusal because the
conflicting option identities are not safely separable by this change. Existing
price checks remain intact. An existing live lead without an option does not
repeatedly queue a complete sibling attempting to introduce that option, whether
the listing step or the seeding step holds it (pinned by
`test_a_live_lead_with_no_size_and_a_new_sized_colour_is_not_requeued_every_run`).
