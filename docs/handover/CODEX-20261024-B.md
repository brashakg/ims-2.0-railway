## Behaviour

The parity card counts catalog products whose SKU matches a catalog variant carrying a Shopify variant ID. Two colours on one website page count as two online colours. Orphan variants and duplicate variant rows do not inflate the numerator. The denominator retains all catalog products, including deliberately archived rows. The old `entities` API object is unchanged; the new `colours_sizes` object carries matching units and the missing-SKU list.

Missing reasons come from current catalog state: archived, taken down, family refusal with its code, held colour with its code, not ready, queued awaiting publish, or not queued. Family reasons reuse the actual read-only family planner. An unreadable mapping join is unavailable, never a fabricated zero; unreadable family readiness is stated as unknown. No old run failure is presented as a current refusal after its input is fixed.

Drift compares title, status, IMS-owned tags, and variant SKU/options/price/compare-at price. Expected values come from the actual family planner and push payload builders. Unmanaged Shopify tags survive the comparison; numeric formatting, tag case, option order, and Colour/Color aliases do not create alarms. Deliberately taken-down products expect DRAFT. Shopify `updatedAt` is retained only as context, never as the trigger. Products without a push timestamp are still compared.

The detector samples up to 50 product listings by default. It reads every variant page for each sampled listing, with bounded batches/pagination. GraphQL errors, missing products, incomplete pages and unreadable IMS plans count as unknown comparisons. The UI names differing fields and shows unknown coverage. Its wording also states that pending IMS edits can differ; content drift does not prove a second writer. Collection timestamp checks are retired; the API explicitly identifies product scope.
